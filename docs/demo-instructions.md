# NodeWeather – інструкція для демо

Цей документ допомагає швидко підготуватися до демонстрації застосунку NodeWeather: як запустити, що показати викладачу та на які технічні моменти звернути увагу.

---

## 1. Як запустити застосунок

### 1.1. Запуск бекенда (API + SQLite)

```bash
cd backend
npm install
npm test
npm start
```

### 1.2. Запуск фронтенду (UI)

```bash
cd frontend
npm install
npm start
```

> Важливо: при локальному запуску фронтенд визначає `API_BASE` як `http://localhost:4000/api`, тому бекенд має бути запущено до відкриття UI.

---

## 2. Що показати на демонстрації

### 2.1. Основний сценарій

1. Вибір міста зі списку (або через пошук).
2. Отримання прогнозу погоди:
   - фронтенд викликає VisualCrossing API;
   - відображається поточна погода, прогноз на декілька днів, піктограми.
3. Додавання міста до улюблених:
   - кнопка «Додати в улюблені»;
   - виклик `POST /api/favorites`;
   - оновлення блока «Улюблені міста».
4. Формування історії:
   - при кожному запиті місто + дата записуються через `POST /api/history`;
   - внизу сторінки показується список останніх запитів.
5. Аналітика:
   - топ міст (`/api/stats/top-cities`);
   - загальна кількість записів (`/api/stats/overview`);
   - кількість запитів за сьогодні (`/api/stats/today`).

### 2.2. Очищення даних

- Показати очищення улюблених (`DELETE /api/favorites`) та історії (`DELETE /api/history`).
- Пояснити, як працює автоочищення старих записів (`DELETE /api/history/cleanup?days=…`).

---

## 3. Що сказати на захисті

### 3.1. Призначення

- Це погодний застосунок, який:
  - показує поточну погоду та прогноз;
  - дозволяє зберігати улюблені міста;
  - веде історію звернень;
  - рахує просту статистику використання.

### 3.2. Архітектура

- Клієнт–серверна архітектура:
  - **Frontend**: HTML/CSS/JS + jQuery, модулі `app.js`, `services/weatherService.js`, `services/storageApi.js`.
  - **Backend**: Node.js + Express, REST API `/api/favorites`, `/api/history`, `/api/stats/*`.
  - **База даних**: SQLite (`weather.db`) з таблицями `favorites` і `history`.
  - **Зовнішній сервіс**: VisualCrossing Weather API.

### 3.3. Зберігання даних

- Основне зберігання:
  - **SQLite** для улюблених міст та історії переглядів.
- На фронтенді:
  - **localStorage** (через `storage.js`) може використовуватись як кеш / для тестів.

### 3.4. Якість коду

- ESLint + Prettier на фронтенді та бекенді.
- Jest + jsdom / supertest для тестування.
- Stryker для мутаційного тестування фронтенду.
- GitHub Actions для автоматичного запуску lint+tests при кожному push.

### 3.5. Подальший розвиток

- Додати авторизацію/профілі користувачів.
- Зберігати більше аналітики (середні температури, графіки за період).
- Зробити кешування відповідей погодного API на бекенді.
- Додати більш розширений UI (фільтри, графіки, темну тему).
